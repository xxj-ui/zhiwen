## 1. 要回答的三个问题

| # | 问题 | 对应指标层 | 现状 |
| --- | --- | --- | --- |
| Q-A | 我的检索有没有把**能回答这个问题的片段**捞上来？ | 检索层 | 完全没有量化，只有"看起来引用了对的文档" |
| Q-B | 回答里的每句话，能不能在检索片段里找到依据？ | 生成层（grounding） | 有 `FALLBACK_TEXT` 兜底，但**阈值不存在**，兜底只在空库时进得去（见 §8.6） |
| Q-C | 改一个参数（`top_k` / `chunk_size` / `rrf_k` / 换 embedding），是变好还是变坏？ | 对照实验 | 无法判断，只能凭手感 |

评测的交付物不是一个分数，而是**在固定语料 + 固定 gold + 固定参数下，可重复跑出的一张三层指标表**，任意两次改动之间可对比。

## 2. 三层指标，别用一层冒充全部

| 层 | 指标 | 取数位置 | 本项目做法 |
| --- | --- | --- | --- |
| 检索 | Recall@k、MRR、nDCG | **直调 `services/retrieval.retrieve()`** 拿 top-(2k~4k) 原始片段与各自排名 | **自算**，不依赖评测框架（原因见 §4.1） |
| 生成 | Faithfulness、FactualCorrectness、AnswerRelevancy | 参考答案 + `retrieved_contexts` + 最终 `response` | 用 RAGAS（LLM-as-judge） |
| 辅助 | BLEU / ROUGE-L / 语义相似度 | 同生成层 | 只作参考项，**不作主指标**（风格差异会把字符串指标拉爆） |

RAGAS 覆盖的是第 2 层（和部分第 3 层）；第 1 层它只能给"LLM 判 claim 归因"，不是检索器召回率。两者不能混着说，报告必须分节。

## 3. 样本契约

### 3.1 四字段（RAGAS `SingleTurnSample` / `EvaluationDataset` 的口径）

| 字段 | 定义 | zhiwen 取数点 | 硬性要求 |
| --- | --- | --- | --- |
| `user_input` | 用户原始问题 | 测试集 | 多轮场景要**照抄** `chat.retrieval_query()` 的拼接方式（上一轮 user + 当前问题），否则召回片段会变 |
| `retrieved_contexts` | **送进大模型的原文片段列表** | `services/retrieval.py:16 retrieve()` 返回的 `chunks[*]["content"]` | 必须是原文，`top_k=5` 条按融合后顺序 |
| `response` | 系统最终回答文本 | 流式 `delta` 拼接结果 = 落库的 assistant 消息 | 走真实生成链路，不手工补 |
| `reference` | 金标准答案 | 人工 / 数据集 | 含"无法从资料回答"类问题时要显式标注 |

可选：`reference_context_id`（金标准片段 id），只在算 ID 级召回时用。

### 3.2 四个必须避开的反例

1. **拿引用卡片当上下文**。`chat.build_citations()` 的 `snippet` 经 `_clean_snippet()` 截到 **100 字**（`SNIPPET_MAX`），而库里片段平均 **463 字**（§6.1 实测）——用 snippet 当 `retrieved_contexts` 会丢掉 **78.4%** 的原文，Faithfulness 与 ContextRecall 双双系统性偏低。必须取 `content` 原文。
2. **拿模型自己的回答当 gold**。`reference` 由被测链路生成 = 自己给自己判卷，FactualCorrectness 恒高。gold 必须来自语料本身或人工。
3. **多轮问题只喂当前一句**。库里 `retrieval_query()` 是"上一轮问题 + 当前问题"拼接，评测只喂当前句会低估召回，把"拼接策略有问题"误判成"检索有问题"。
4. **把题库导入知识库**。`data/crud_split/split_merged.json` 里同时有 `questions`、`answers` 和 `news1..3`——导入后检索能直接命中"答案原文"，Recall 与 Faithfulness 双双虚高，整轮评测作废（且 `.json` 本就被 `ALLOWED_SUFFIXES` 拒收）。**评测集只进评测脚本，`reference` 只在打分时打开。**

### 3.3 采集流程（一次跑完，样本落盘复用）

```
for q in testset:                       # 问题 + reference 先固定
    ctx   = retrieve(container, q)      # 同步版，拿原始 chunks（含 id）
    resp  = run_real_answer(q, ctx)     # 真实 llm.answer(stream=False 或拼 SSE delta)
    row   = {user_input, retrieved_contexts:[c["content"]], response, reference,
             retrieved_context_ids:[c["id"]], params:{top_k, recall_k, rrf_k, chunk_size, model}}
```

`params` 必须逐条落盘：两次 run 的 `chunk_size` 不同就不是同一个实验。

### 3.4 样本量：30 起步，100 看差异

按 Wilson 区间算的 95% 置信半宽（**推算**，二项分布假设）：

| 题数 | 真值 0.8 时的区间 | 半宽 | 能分辨的差异 |
| --- | --- | --- | --- |
| 30 | [0.63, 0.90] | ±13.9 pp | 只有 ≥25 pp 的改动可信 |
| 50 | [0.67, 0.89] | ±10.9 pp | ≥20 pp |
| 100 | [0.71, 0.87] | ±7.8 pp | ≥15 pp |

结论：**30 题只能看"有没有大坑"，验证参数微调要 100 题起**。一题权重在 100 题里是 1 pp，别拿 3 pp 的差异下结论。

E1 的 30 题**直接用 CRUD-RAG 自带 gold**（2026-11-05 修订）：在合格池里分层抽 30 道，落 `evals/datasets/e1-dataset.jsonl`，口径与来源记在 `evals/datasets/e1-dataset.meta.json`。

"合格"= 每篇 gold 都满足 `backable ≥ 0.80`（40 字不重叠窗能在语料正文找到的比例）且 `best_chunk ≥ 0.50`（单块最高覆盖）。按此口径全量重筛 2,394 题：**1doc 13 / 2doc 141 / 3doc 105 = 259 道合格**（原"4 偏移"口径的 368 道已作废，v1 数据集归档在 `evals/datasets/_superseded/e1-dataset.v1.jsonl`）。E1 按等比抽 **2 / 16 / 12 = 30 题**（同 event 去重，seed 20261105，覆盖 30 个不同事件）。人工出题降为可选补充（用于测"我们自己文档"的场景）。

## 4. 指标选型

RAGAS 0.4.3 的每指标 LLM 调用数（**实测**：按仓库 `src/ragas/metrics/collections/*/metric.py` 里 `agenerate()` 调用点计数）：

| 指标 | LLM 调用/样本 | 需要 reference | 测什么 | 本项目 |
| --- | --- | --- | --- | --- |
| `Faithfulness` | 2（拆断言 + 逐条 NLI） | 否 | 回答是否超出上下文（幻觉率） | **采用（核心）** |
| `ContextRecall` | 1 | **是** | gold 里的断言被检索覆盖多少 | 采用（有 gold 时） |
| `ContextPrecision` | 2 | 否（有 WithoutReference 版） | 检索片段里有用信息占比 | 采用（无 gold 时替 ContextRecall） |
| `AnswerRelevancy` | 1 + 2 次 embed | 否 | 回答跑不跑题 | 采用，embedding 用本地 bge |
| `FactualCorrectness` | 2 | **是** | 与 gold 的事实一致度 | 可选（与 Faithfulness 有重叠） |
| `BLEU` / `ROUGE` / `SemanticSimilarity` | 0 | **是** | 字面/语义相似 | 只作参考列 |

**最小基线组合（E1）**：`Faithfulness + ContextRecall + AnswerRelevancy`（有 gold）；无 gold 时退 `Faithfulness + ContextPrecision(WithoutReference)`。

### 4.1 检索层必须自算，不能拿 ContextRecall 顶

- `ContextRecall` 是"LLM 判断 gold 的断言能否在检索片段中找到归因"，**与检索器召回率不是一回事**：检索到 4 条全错的片段但恰好覆盖了 gold 的断言，它照样给 1.0。
- 自算口径：`retrieve()` 目前只回 `top_k=5`，算 Recall@k 需要 **top-(2~4)k** 原始候选 → 评测时显式调 `retrieve(container, q, top_k=40)`，再按 gold 片段 id 或 gold 正文模糊匹配定位名次。
- **命中判定**先看语料物理形态：片段被切分后 gold 与 chunk 不是包含关系，用"gold 正文 20 字滑窗、命中 ≥3 个不重叠片段算命中"，写进报告方法节。
- 已备好的快捷路径：RAGAS 有 `IDBasedContextRecall`（`retrieved_context_ids` vs `reference_context_ids`），zhiwen 的 chunk 有自增 `id`，**只要 gold 标到片段 id 就能用它**，前提是语料不变（重新导入会换 id）。

### 4.2 不做的事

- 不测多轮指标（10 §3）。
- 不测续写/摘要类任务（本项目无此功能）。
- 不与论文基线比"优于/劣于"：chunk / top_k / embedding / LLM 四件套对齐不了，只做纵向自比。

## 5. 裁判模型：DeepSeek（含同源偏差声明）

```python
import instructor
from openai import AsyncOpenAI
from ragas.llms import llm_factory

client = AsyncOpenAI(base_url="https://api.deepseek.com", api_key=os.environ["DEEPSEEK_API_KEY"])
judge  = llm_factory("deepseek-chat", client=client,
                     mode=instructor.Mode.JSON,   # DeepSeek 无 json_schema，只能走 json_object
                     temperature=0)
```

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 结构化输出 | 走 `Mode.JSON`（默认值），不用 `JSON_SCHEMA` | DeepSeek 只支持 `response_format={"type":"json_object"}`（**推断，待首次实跑验证**） |
| 温度 | 0 | judge 要可复现 |
| 同源偏差 | **必须写进报告方法节**：裁判与被测模型同为 `deepseek-chat`，倾向于给"自己风格"的回答更高分，绝对值乐观偏 ~未知幅度；**趋势对比（改前/改后）比绝对值可信** | 2026-11-05 裁决 |
| 中文 prompt | 0.4 已移除 `ragas.prompt.adapt_prompts` / `Language`（实读 `src/ragas/prompt/__init__.py` 无此导出）。默认指标 prompt 是英文，中文语料下需替换 `metric` 内部的 prompt 对象，或自建 `DiscreteMetric` 写中文判据 | 源码实测 |
| 缓存 | 开关可配 `DiskCacheBackend`；第一轮先用它压重复调用成本 | 官方 `llm_factory(cache=...)` |
| 备用裁判 | 若同源偏差被质疑，换 Qwen/GLM/OpenAI 作为第二裁判做交叉；本轮不做 | 待定 |

## 6. 成本模型（口径先说清）

### 6.1 实测口径

| 量 | 实测值 | 怎么测的 |
| --- | --- | --- |
| 片段平均长度 | **463 字**（p50 473 / p95 498 / max 500，共 8935 块 / 2 文档） | `select avg(length(content)) ... from rag_chunks`（2026-11-05，真库 `zhiwen`） |
| 汉字 → token | **0.614 tok/汉字** | 取 5 条真实片段（2337 字）打一次 `deepseek-chat` 调用读 `usage.prompt_tokens` = 1434（含 chat 模板固定开销） |
| tiktoken 近似 | cl100k_base = **1.089 tok/汉字**，比 DeepSeek 实际**高估 77%** | 同一批文本用 `tiktoken` 计数 |
| 检索耗时 | 1.07 s（单文档 1 片段） | 08 §3.4 |

> 记 token 预算时**不要用 tiktoken 估 DeepSeek**，会多报一倍。

### 6.2 单样本 token 预算（**推算**，基于 §6.1 与 §4 的调用数）

`top_k=5` → 上下文 ≈ 2315 汉字 ≈ **1421 tokens**。

| 调用 | 输入 token | 输出 token |
| --- | --- | --- |
| Faithfulness #1 拆断言 | ~500 | ~250 |
| Faithfulness #2 逐条 NLI（含全部上下文） | ~2021 | ~120 |
| ContextRecall（含 gold） | ~1971 | ~90 |
| AnswerRelevancy | ~602 | ~150 |
| **合计/样本** | **≈5.1 k** | **≈0.6 k** |

### 6.3 三档规模

| 题数 | judge 调用数 | 输入 tokens | 输出 tokens | 串行耗时（6 s/调用） | 8 并发 |
| --- | --- | --- | --- | --- | --- |
| 30 | 120 | ≈153 k | ≈18 k | ≈12 min | ≈1.5 min |
| 50 | 200 | ≈254 k | ≈31 k | ≈20 min | ≈2.5 min |
| 100 | 400 | ≈509 k | ≈61 k | ≈40 min | ≈5 min |

金额 = 上表 token × DeepSeek 后台当前价目（**不在此写死单价**，价目会变；首次实跑后把 `usage` 回填成实测金额）。

**失效条件**：`top_k` 调大 / 片段变长 / 换成 1000 字 chunk，成本近似线性放大；`top_k=10` 时单样本输入翻倍到 ~9 k。

## 8. 风险与失效条件

| # | 风险 | 影响 | 处理 |
| --- | --- | --- | --- |
| 8.1 | 语料里根本没有 gold 对应内容 | 召回恒 0，整轮数据作废 | 先量"gold 可定位率"，不可定位的子集排除出主指标 |
| 8.2 | 裁判与被测同源（DeepSeek 评 DeepSeek） | 绝对值乐观、方差偏小 | 报告方法节声明；以趋势对比为主 |
| 8.3 | 中文语料 + 英文 judge prompt | 断言拆分粒度与判据漂移，分数不可跨语言比 | E1 必做一次人工抽检 3 条 reason |
| 8.4 | DeepSeek 结构化输出失败 | 指标抛异常、样本丢失 | runner 记录失败样本数，失败率 >2% 即停跑修 |
| 8.5 | 片段被切分截断（p95=498 ≈ `chunk_size` 500） | 断言跨片断开，Faithfulness 偏低 | 报告里写明；对照"加大 overlap 100→150"单独一轮 |
| 8.5b | **语料形态**：CRUD-RAG 的 txt 是 1,930 条新闻首尾相接，被 `load_txt` 当作一个单元切分 → **7.8%（697/8,935）的块跨两条新闻**，指代可能被污染（e1-008 即命中此情况） | 该类题上模型倾向拒答，Faithfulness/准确性被低估 | 报告方法节声明跨条率；抽检命中样本并单列；**不改切分器**（PDF/Excel 按页/表切分，无此问题） |
| 8.6 | 兜底分支永远走不到 | "编造无答案内容"测不出来 | 检索无相似度阈值（`recall_k=20` 凑满 `top_k`），库外问题也会拿到 5 条片段 → 拒答能力必须单独用库外问题集测 |
| 8.7 | 多轮拼接 | 单句评测低估召回 | 照抄 `retrieval_query()` |
| 8.8 | 样本量不足就下结论 | 3 题差异当结论 | §3.4 的置信区间表写进报告 |
| 8.9 | 语料变化导致 chunk id 漂移 | `IDBasedContextRecall` 失效 | 重新导入后必须重标 gold；gold 用正文定位更稳 |

## 9. 验收口径（评测本身算做完的标准）

1. `evals/runs/<run_id>/config.json` 能复现同一次跑（参数齐全、含语料快照说明）。
2. `samples.jsonl` 每行五字段齐全，`retrieved_contexts` 为原文（非 snippet）。
3. `report.md` 三层分节，每个数字标「实测/推算」，附方法节（命中判定、gold 可定位率、样本量、置信区间）。
4. 报告明确写出裁判同源偏差与失效条件。

### 11.1 两条根因

1. **样本筛选口径过松**：原口径是"30 字窗 × 4 个偏移命中任意一处"，会把"只有片段重合"的题误判为可测。e1-001 的 gold 前 250 字整段不在库，4 个关键标准名中 3 个在全库 8,935 块里**完全不存在**，检索却已把唯一相关块排到第 1。
2. **语料形态导致块跨两条新闻**：块 `id=800`（483 字）前半段是"大学生文化体验营"报道（刘复国、朱小健），位置 262 才出现"据悉，此次活动由……共同主办"，位置 319 才是"文艺营开营"。原因不是切分器缺陷——`split_chunk` 按 `。！？；\n` 句子边界聚合，且只在单个文档单元内切分；是 CRUD-RAG 的 txt 把 1,930 条新闻首尾相接、`load_txt` 视作**一个单元**，句子边界不构成块边界。全库量化：**697/8,935 块（7.8%）** 内含第二条新闻的日期头。指代在块内不可判定，模型拒答属合理保守。

### 11.5 P1 检索基线首轮结果（30 题，2026-11-05 实测）

**裁判可信度（负向对照）**：取 e1-001 的回答替换成一段编造内容（"标准全部属医疗器械领域""该规范已废止"），
faithfulness 由 **1.0 掉到 0.0**（`ragas-control.jsonl`）。说明裁判确实在按上下文核对，不是一律给高分。

**一个交叉验证**：e1-028（问河北省幼儿园收费）模型拒答，同时 `context_recall = 0.333`——
即"该答的信息确实没被检索到"，拒答是**对的**，不是模型偷懒。

**三个必须连读的限制**

1. **天花板效应**：`faithfulness` 25/30 满分，均值 0.972 已经没有区分度；真正有信号的是尾部 3 题（e1-007 0.667、e1-028 0.800、e1-020 0.850）。要提高分辨力只能加难样本（多文档、跨段、易混事件），不是换指标。
2. **同源偏差**：裁判与被测都是 `deepseek-chat`，绝对值偏乐观，只能纵向比。
3. **严格 gold 口径**：`context_recall` 用 gold 断言归因判定，同事件其他报道不算命中，天生偏低。

**两个踩坑（都已解决，记下来避免重犯）**

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| langchain 1.x 不兼容 | `ModuleNotFoundError: langchain_community.chat_models.vertexai`（import ragas 就崩） | `langchain<1` 系列钉版本，写入 `requirements-eval.txt` |
| 裁判 `max_tokens` 不足 | 长答案（>400 字）拆断言时抛 `IncompleteOutputException`，**15/30 题无分** | `llm_factory(..., max_tokens=4096, temperature=0)`；v1 结果归档为 `ragas-v1-max1024.*` |
| `llm_factory(mode=...)` 不可传 | `AsyncCompletions.create() got an unexpected keyword argument 'mode'` | ragas 内部已固定 `Mode.JSON`（`llms/base.py:556`），调用方不要传 |

#### 11.8.3 拒答必须分层报（本轮最重要的口径发现）

| 分组 | 题数 | faithfulness | context_recall |
| --- | --- | --- | --- |
| 全体 | 259 | 0.963 | 0.856 |
| 非拒答 | 244 | **0.976** | **0.879** |
| 拒答 | 15 | **0.761** | **0.489** |

- 拒答题的 `context_recall` 只有 0.489，说明**"模型说没资料"和"证据确实缺失"高度一致**——拒答不是偷懒（对照 30 题批次的 e1-028 同样规律）。

- `context_recall` 191/259（73.7%）满分，区分度靠 66 题 <0.8。
