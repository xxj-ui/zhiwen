## 1. 文档说明

### 1.1 为什么要单独有一份需求分析

现有的 `SRS.md` 是**规格层**文档：逐条写清"系统必须做什么、做到什么程度、怎么验收"，并混入了数据模型与接口契约（第 5、6、7 章）。它回答的是"做什么"，但没有回答"为什么是这些需求"——缺角色画像、使用场景、用例、优先级与追溯。

本文补的就是这一层，并且把 SRS 中的需求内容**就地吸收**，让读者只看这一份就能理解需求全貌；需要精确到字段、接口、错误码时再翻 SRS。

### 1.2 四份文档的分工

```text
本文 00.需求分析        为谁、为什么、怎么用、先做什么、需求的来源与优先级
   │  提供依据
   ▼
SRS v0.3                逐条可验收的要求（FR / NFR / BR / AC）+ 接口与数据契约（含设计内容）
   │  提供依据
   ▼
设计 01 v0.8            功能清单 F-01~F-30、模块划分 M1~M7、模块关系、业务流程
   │  提供依据
   ▼
原型 prototype/         已确认的交互蓝本（视觉、交互、文案、演示数据）
```

规则：
- 本文与 SRS 冲突时**以 SRS 为准**，并回写本文。
- 本文不复述接口契约、表结构、错误码（在 SRS 第 5/6/7 章），只引用。
- 本文引用的功能编号（F-xx）以设计 01 为准，需求编号（FR/NFR/BR/AC）以 SRS 为准。

### 1.3 术语

沿用 [SRS 1.3](SRS.md#13-术语)：知识库、文档、chunk、稠密检索、关键词检索、RRF、引用、会话。本文新增：

| 术语 | 说明 |
| --- | --- |
| 用户故事（US） | 从一个使用情境出发的一段完整体验描述，含触发、步骤、期望结果 |
| 用例（UC） | 系统对外提供的一次完整能力，含前置条件、主流程、备选流程、后置条件 |
| 追溯矩阵 | 需求编号 → 功能编号 → 原型位置 → 验收编号 的对照表，用于证明"无遗漏、无膨胀" |

## 2. 背景与问题定义

### 2.1 现状

已有一套可用的 RAG 内核（加载 → 切分 → 向量化 → pgvector 存储 → 关键词召回 → RRF 融合 → DeepSeek 生成），但**只有命令行入口**：

| 现状 | 后果 |
| --- | --- |
| 入库靠 `python -m server.main --build <路径>` | 只能处理本机已有目录，无法在浏览器里选文件 |
| 问答靠 `--ask "问题"` | 一次只能问一句，结果打印在终端，看不到引用来源卡片 |
| 没有文档台账 | 不知道知识库里有哪些文档、各有多少片段、什么时候更新的 |
| 没有历史 | 问过的问题与回答无法回看 |
| 覆盖/删除靠手工 SQL 或重跑建库 | 容易留下半成品数据，无法保证"要么全成、要么不留痕" |

### 2.2 要解决的问题

1. **入口问题**：让非技术用户也能把资料"送进来"（拖拽/选择文件），而不是敲命令。
2. **可见性问题**：让用户随时知道知识库里有什么、有多少、更新到哪一版。
3. **可信问题**：回答必须有出处（文件名 + 位置 + 片段），而不是一段无法核对的文字。
4. **留痕问题**：问过的问答要能回看，刷新页面/重启服务不丢。
5. **一致性问题**：覆盖与删除必须原子，任何一步失败都不能破坏已有数据。

### 2.3 成功判据

| 判据 | 度量 |
| --- | --- |
| 无需命令行即可完成全流程 | 从双击启动到提问，全程只用浏览器 |
| 回答可核对 | 每条回答下方有引用卡片，文件名与实际文档一致 |
| 知识库状态可信 | 列表里的文档 = 能被检索到的内容（删除即失效） |
| 异常可解释 | 每个失败都有中文原因，不需要看日志才能判断 |

## 3. 用户角色与使用环境

### 3.1 角色

| 角色 | 描述 | 关注点 |
| --- | --- | --- |
| **本人（唯一用户）** | 本机使用者，具备基本文件管理与浏览器操作能力，不需要培训 | 快速导入资料、问到有依据的答案、知道答案出自哪份文件 |

本期**没有**管理员、访客、多用户、权限角色（SRS D-1 / 1.2 明确排除）。

### 3.2 使用环境与习惯

| 维度 | 事实（来自 SRS 2.3 / 2.5） | 对需求的影响 |
| --- | --- | --- |
| 设备 | Windows 11 本机，桌面浏览器宽度 ≥ 1280px | 不做移动端适配（NFR-5） |
| 网络 | 本机访问 `127.0.0.1`，需能访问 DeepSeek API | 无跨域与公网攻击面（NFR-3） |
| 规模 | 几十份文档，chunk 总量 ≤ 5000 | 列表全量展示、不分页（D-10） |
| 频率 | 资料导入是低频重操作（一次几份到二十份），提问是高频轻操作 | 上传可以慢但必须给出逐文件进度；提问必须流式首字快 |
| 数据敏感度 | 课程资料、实验笔记等本机文件 | 原文件留在本机，不入第三方存储 |

### 3.3 关键约束（需求级）

1. 单用户、无登录、只监听 `127.0.0.1`（D-1）。
2. 不做 OCR：扫描版 PDF 无法入库，必须明确告知而不是静默失败。
3. 不做多轮对话：每次提问独立检索，不拼历史上下文（D-6 / BR-5）。
4. 原文件保留在本机，删除文档时一并删除（D-4）。
5. 所有用户可见文案为中文（SRS 2.4.6）。

## 4. 用户场景（用户故事）

> 每条场景都落到具体需求与原型位置，避免"想当然的新功能"。

### US-1 第一次把资料倒进去

- **背景**：我手上有 8 份课程资料（3 个 PDF、2 个 DOCX、1 个 MD、1 个 TXT、1 个 XLSX），散在文件夹里。
- **触发**：打开「知识库」页，看到"还没有文档"的空状态和上传入口。
- **步骤**：一次拖进 8 个文件 → 每行显示"解析 / 切分向量化 / 写入" → 逐个变成"上传完成"。
- **期望**：8 行都有结果；成功项进入列表并显示片段数；失败项标红并写明原因，不出现在列表里；无需刷新页面。
- **对应**：FR-1、BR-8、BR-10、F-01~F-06、AC-1/AC-3/AC-12/AC-13；原型 `#dropzone` → `#uploadQueue` → `#docTableBody`。

### US-2 问一个只有资料里才有答案的问题

- **背景**：我想确认"王教授在哪个教室上课"。
- **触发**：在问答页输入问题，Enter 发送。
- **步骤**：显示"正在检索知识库" → 回答逐字出现 → 下方出现引用卡片（文件名 / 位置 / 片段摘要）。
- **期望**：回答里带 `[1]` 这样的编号，编号能对上引用卡片；片段摘要足以让我判断"答案确实出自这里"。
- **对应**：FR-4、FR-5、BR-6、BR-7、F-12~F-20、AC-5；原型 `#chatForm` / `.retrieval-status` / `.citations`。

### US-3 资料更新了，我要用新版

- **背景**：课程安排改了时间，我把同名的新版 `课程安排.docx` 拖进来。
- **期望**：列表仍只有一条该文档；该文档浮到最上面，片段数是新版的；**旧的片段不再被检索到**；如果新版解析失败，旧版必须原样还在。
- **对应**：FR-1（覆盖）、BR-1、BR-2、Q1、F-04、AC-2；原型上传队列的"已覆盖同名文档"提示。

### US-4 一份资料过时了，删掉它

- **背景**：去年的实验指导书不再适用。
- **期望**：二次确认弹窗明确说"片段与原文件一并删除，不可恢复"；确认后列表移除，再问相关问题不应再命中该文档的内容。
- **对应**：FR-3、BR-3、BR-4、F-10、F-11、AC-4；原型文档表格行删除按钮 + `#modalBackdrop`。

### US-5 三天后回看上次的问答

- **背景**：我上周问过"实验报告什么时候交"，想再看一遍当时的回答和出处。
- **期望**：侧边栏按时间倒序列出历史，点击即恢复问题、回答、引用卡片；**不重新调用大模型**；刷新页面后仍在。
- **对应**：FR-6、F-21~F-24、AC-7；原型 `#historyList` / `loadConversation`。

### US-6 出了问题我要知道是哪一环

- **背景**：提问后一直没出字，或者回答到一半报错。
- **期望**：明确告诉我"大模型超时"还是"数据库不可用"还是"没配置 Key"；给出重试入口；不要把失败写成一条空回答留在历史里。
- **对应**：FR-4 异常表、FR-7、F-18、F-27、F-28、AC-8；原型目前**只有生成中态**，失败态/降级态由设计 01 §9 的 G1~G3 登记，待后续补齐。

### US-7 知识库里没有的东西，它不该编

- **背景**：我随口问了课程资料里没写的内容。
- **期望**：直接回答"根据已有资料无法回答"，并给"去上传文档"的引导；这次问答仍算一次有效问答，可以回看。
- **对应**：FR-4 第 4 步、BR-6、Q7、Q10、F-15、AC-6；原型 `findMatch` 的兜底分支 + `appendDocsAction`。

| 编号 | 用例 | 主责模块 | 需求 | 验收 |
| --- | --- | --- | --- | --- |
| UC-01 | 批量上传文档（含同名覆盖、单文件失败隔离） | M1 → M2 | FR-1 | AC-1/2/3/9/12 |
| UC-02 | 查看知识库列表与统计 | M1 | FR-2 | — |
| UC-03 | 删除文档 | M1 → M3 | FR-3 | AC-4 |
| UC-04 | 基于知识库提问（含无结果兜底、生成失败重试） | M3 → M4 → M5 | FR-4 | AC-5/6/8/11 |
| UC-05 | 回看问答历史 | M6 | FR-6 | AC-7 |
| UC-06 | 删除历史记录 | M6 | FR-6 | — |
| UC-07 | 查看系统状态 / 冷启动等待 | M7 | FR-7 | — |
| UC-08 | 新建对话（清空当前视图） | M6 + UI | FR-6（交互） | — |

### UC-01 批量上传文档

- **前置**：服务已启动；数据库可连接。
- **主流程**：选择/拖拽 1~20 个文件 → 逐文件校验（扩展名、大小、空文件、文件名安全）→ 解析 → 切分 → 向量化 → 写入（同名则一次性替换）→ 逐文件反馈 → 刷新列表与统计。
- **备选 1（超过 20 个）**：整批拒绝，本次一个都不处理（Q8 / BR-8）。
- **备选 2（单文件失败）**：该文件不写库、不落盘，其他文件继续（FR-1 步骤 5 / BR-10）。
- **备选 3（同名覆盖中失败）**：旧文档与旧原文件保持原样（Q1 / BR-2）。
- **备选 4（解析为空/扫描件）**：标记失败并提示"可能是扫描件或空文档"（SRS FR-1 异常表）。
- **后置**：列表只含成功文档；关键词索引随写入自动更新（BR-4），上句列表返回时即已可检索。
- **功能编号**：F-01~F-06；**模块**：M1、M2。

### UC-02 查看知识库列表与统计

- **主流程**：进入知识库页 → 拉取全量列表（按最近更新倒序）→ 表格渲染（文件名、类型、大小、片段数、最近更新、删除）→ 标题区与导航徽标显示文档数与片段总数。
- **备选（空库）**：展示空状态 + 上传入口。
- **功能编号**：F-07、F-08、F-09。

### UC-03 删除文档

- **主流程**：点删除 → 二次确认（文案含"片段与原文件一并删除、不可恢复"）→ 事务内删 chunk + 文档记录 → 删磁盘原文件 → 列表与统计刷新 → Toast。
- **备选 1（文档已不存在）**：接口 404，前端按"已删除"友好提示，不展示错误态（FR-3 异常表）。
- **备选 2（原文件已手工删除）**：仍删数据库记录并返回成功。
- **备选 3（数据库删除失败）**：返回 500，不删原文件。
- **后置**：该文档内容不再被检索命中（F-11）。
- **功能编号**：F-10、F-11。

### UC-04 基于知识库提问

- **前置**：问题非空、≤ 500 字（前端拦截，后端 422 兜底）。
- **主流程**：提交 → 两路召回各 20 条 → RRF（k=60）取前 5 → 生成引用条目并确定编号 → SSE 下发 `citations` → 流式 `delta` → 保存会话 → `done`。
- **备选 1（两路均空）**：不调大模型，返回固定话术"根据已有资料无法回答"，仍保存历史（Q7）。
- **备选 2（大模型失败）**：终止流、下发 `error`、「重试」入口，**不保存空历史**（AC-8）。
- **备选 3（生成中操作）**：提问/切历史/删历史/新建对话一律拦截并提示，仅允许切到知识库页（Q12）。
- **后置**：侧边栏新增一条历史，标题取问题前 30 字。
- **功能编号**：F-12~F-20；**模块**：M3、M4、M5。

### UC-05 回看问答历史

- **主流程**：打开页面 → 拉历史列表（倒序，最多 50 条）→ 点击某条 → 读取会话详情 → 渲染问题/回答/引用卡片。
- **约束**：只读，不检索、不调大模型（F-24）。
- **功能编号**：F-21~F-24。

### UC-06 删除历史记录

- **主流程**：点删除 → 二次确认 → 事务内删消息 + 会话 → 刷新侧边栏 → 若删的是当前会话则回到欢迎页。
- **功能编号**：F-25。

### UC-07 查看系统状态 / 冷启动等待

- **主流程**：页面加载 → 请求健康检查 → 数据库 / 嵌入模型 / 大模型 Key 三项状态 → 任一异常时顶部显示降级。
- **约束**：首次加载模型期间，问答入口提示"模型加载中"，发送按钮禁用（FR-7、SRS 8.4）。
- **功能编号**：F-27、F-28。**当前原型未演示冷启动与降级**（G2/G3）。

### UC-08 新建对话

- **主流程**：点"新建对话" → 清空当前视图 → 回到欢迎页（含示例问题）→ **不创建空会话**。
- **约束**：生成中禁止（Q12）。
- **功能编号**：F-26。

## 6. 需求清单（吸收 SRS 内容）

> 本节收录 SRS 中**属于需求**的内容：范围、功能需求要点、非功能指标、业务规则（全量）、界面要求。压缩到"能判断需求是否成立"的粒度，作为第 4、5 节场景与用例的对照物。
> 不复述的是：SRS 里 FR 逐条的输入 / 处理 / 输出 / 异常明细表，以及第 5~7 章的设计内容（架构、表结构、接口契约）——它们的读者和改动频率与需求不同，重复一遍会产生两份事实源。

### 6.1 范围

**本期包含**：本机单用户 Web 应用；文档批量上传、列表、整份删除；六种格式（PDF / DOCX / MD / TXT / XLSX / CSV，不含扫描件）；同名覆盖；单轮问答；SSE 流式回答与引用来源；问答历史保存与回看。

**本期不包含**：多用户与权限；OCR；多轮对话与查询改写；文档版本管理与回滚；公网部署/HTTPS/反向代理/容器化；rerank；文档在线预览与编辑；移动端适配；按单份文档筛选问答范围。

### 6.2 功能需求（7 条）

| 编号 | 需求 | 一句话规则 | 验收 |
| --- | --- | --- | --- |
| FR-1 | 文档批量上传 | 1~20 个文件，单文件 ≤ 50 MB；逐文件校验 → 解析 → 切分 → 向量化 → 写入；同名覆盖"先就绪后替换"；单文件失败隔离；失败不落库不落盘 | AC-1/2/3/9/12 |
| FR-2 | 文档列表 | 字段：文件名、类型、大小、片段数、最近更新；按最近更新倒序；每次进入或上传后刷新；只含成功文档；空库有引导；展示文档数与片段总数 | — |
| FR-3 | 文档删除 | 二次确认 → 事务内删 chunk + 文档记录 → 删原文件 → 关键词索引自动更新；不存在返回 404（前端按"已删除"提示）；原文件已缺失仍判成功 | AC-4 |
| FR-4 | 基于知识库问答 | 问题 ≤ 500 字；稠密 20 + 关键词 20 → RRF k=60 → 取 5；两路皆空不调大模型返回固定话术；有结果则流式生成并下发引用；结束后存历史 | AC-5/6/8/11 |
| FR-5 | 引用来源 | 序号与资料编号一致；字段：序号、文件名、位置（PDF 页码 / 其余"全文"）、片段摘要（前 100 字）；统一标"引用来源"，不判是否真被引用、不支持展开 | AC-5 |
| FR-6 | 问答历史 | 每次提问一个会话（标题取问题前 30 字）；保存用户消息与助手消息（含引用快照）；倒序列表、回看只读、可删单条；生成失败不存、无结果要存 | AC-7 |
| FR-7 | 系统状态 | 健康检查返回数据库连通性、嵌入模型是否加载、大模型 Key 是否配置；冷启动期间前端提示"模型加载中" | — |

### 6.3 非功能需求（6 条）

| 编号 | 维度 | 指标 / 要求 |
| --- | --- | --- |
| NFR-1 | 性能 | 检索 P95 ≤ 300 ms（热态，≤5000 chunk）；首字延迟 ≤ 3 s；单个 50 页 PDF 入库 ≤ 60 s；文档列表 ≤ 200 ms；历史列表 ≤ 200 ms；冷启动额外约 10 s 且界面有提示 |
| NFR-2 | 可靠性 | 上传/删除幂等；覆盖失败保留旧数据；单文件失败不阻断同批；关键词索引由 PostgreSQL 维护，不依赖进程内状态 |
| NFR-3 | 安全 | 仅监听 `127.0.0.1`；API Key 只在环境变量；扩展名白名单 + 可解析性校验；文件名清洗防路径穿越；存储名由服务端生成；上传目录不在静态资源范围 |
| NFR-4 | 易用性 | 全中文；异步操作有加载态、失败有原因；删除必须二次确认；Enter 发送 / Shift+Enter 换行 |
| NFR-5 | 兼容性 | Chrome / Edge 最近两个大版本；≥ 1280px；不保证移动端 |
| NFR-6 | 可维护性 | 路由 / 服务 / 内核分层，路由不直接操作数据库；检索、切分、文件限制集中配置；关键路径有日志（上传、删除、检索耗时、生成耗时、异常） |

### 6.4 业务规则（10 条）

| 编号 | 规则 |
| --- | --- |
| BR-1 | 同名文件视为同一文档，上传即覆盖旧版本（不区分大小写） |
| BR-2 | 覆盖时先完成新数据的解析、切分、向量化，再一次性替换旧 chunk 与原文件；任一步失败则旧数据与旧原文件保持原样 |
| BR-3 | 删除文档时在同一事务内先删其全部 chunk 记录、再删文档记录，并删除磁盘原文件 |
| BR-4 | 上传与删除后关键词索引须立即可用：PostgreSQL 随写入自动维护，无需显式重建 |
| BR-5 | 每次问答独立检索，不携带历史上下文 |
| BR-6 | 检索无结果时不调用大模型，返回固定话术 |
| BR-7 | 引用编号按提供给大模型的资料顺序生成 |
| BR-8 | 单文件 ≤ 50 MB、单次 ≤ 20 个、问题 ≤ 500 字；单次超过 20 个整批拒绝 |
| BR-9 | 支持 `.pdf` / `.docx` / `.md` / `.txt` / `.xlsx` / `.csv`；不支持 `.doc` / `.xls` |
| BR-10 | 上传失败的文件不写入文档表、不保留原文件，仅返回失败原因 |

### 6.5 界面需求

| 区域 | 要求 |
| --- | --- |
| 布局 | 顶部导航（问答 / 知识库，URL 锚点记忆）+ 左侧历史侧边栏（可折叠）+ 右侧内容区 |
| 问答页 | 输入框固定底部（Enter 发送 / Shift+Enter 换行、字数 0/500）；消息区分用户与助手；回答流式渲染 + 光标；引用卡片在回答下方；空库/无结果显示引导；首次进入展示欢迎页与 4 条示例问题 |
| 知识库页 | 上传区（点击 + 拖拽，标注支持格式与限制）；上传队列逐文件显示阶段；文档表格（文件名、类型、大小、片段数、最近更新、删除）；空状态引导；删除二次确认 |
| 状态反馈 | 上传中显示进度；模型冷启动提示；检索中禁用输入；生成中整体只读（仅允许切知识库页）；错误明确原因可重试 |

## 7. 需求优先级

沿用设计 01 §2.2 的口径：**核心**＝SRS 明确要求且进验收标准；**重要**＝SRS 要求但无独立验收项；**可选**＝SRS 标注可选（本期均不实现，见 8.3）。

| 优先级 | 数量 | 功能编号 |
| --- | --- | --- |
| 核心 | 25 | F-01~F-07、F-10~F-25、F-27、F-30 |
| 重要 | 5 | F-08 知识库统计、F-09 空状态引导、F-26 新建对话、F-28 冷启动提示、F-29 导航与锚点 |
| 可选 | 0 | —（SRS 中两处"可选"：取消未开始文件、历史滚动加载更多，本期均不做） |

**需求层面的优先级判断**

1. 先通"导入 → 检索 → 回答 → 引用"这条主线（FR-1 / FR-4 / FR-5），否则系统没有价值。
2. 其次"可见与可回看"（FR-2 / FR-6），决定这个系统能不能被长期用下去。
3. 最后"删除与状态"（FR-3 / FR-7），是维护成本与信任感，不做会积累脏数据。
